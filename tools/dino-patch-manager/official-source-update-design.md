# 공식 LilacAnime 소스 폴더 업데이트 설계

## 범위

관리자는 설치된 앱의 NSIS 업데이트와 소스 폴더 업데이트를 별개의 작업으로 취급한다. 현재 구현은 공식 GitHub 최신 릴리스 메타데이터 조회만 지원하며, 다운로드·설치·소스 교체는 지원하지 않는다. GUI의 설치 승인은 안전한 설치 기능을 의미하지 않으며, 승인 요청도 실제 업데이트를 시작하지 않는다.

공식 v0.5.55 릴리스에는 Windows 설치 프로그램이 안내되어 있다. 저장소 README는 이 설치본이 설치된 앱을 대상으로 하고, 개발 소스는 `npm install` / `npm start`로 실행하도록 설명한다. 따라서 설치 프로그램을 실행하는 것은 이 관리자가 수정하는 소스 트리를 갱신하는 방법이 아니다. [v0.5.55 릴리스](https://github.com/whispelyn-byte/LilacAnime-desktop/releases/tag/v0.5.55), [공식 저장소](https://github.com/whispelyn-byte/LilacAnime-desktop)

## 향후 다운로드 승인 전 조건

1. GitHub API 응답의 저장소 URL, 릴리스 태그, 태그가 가리키는 commit SHA 및 commit tree SHA를 확인한다. 네트워크 조회 오류는 패치나 원본 파일 손상으로 분류하지 않는다.
2. 업데이트 전에 대상 앱의 구조, 공식 버전, 패치 상태, 실행 중인 LilacAnime 프로세스, 공식 파일 및 사용자 수정 파일을 읽기 전용으로 검사한다.
3. 사용자가 버전·변경 내용·대상 경로를 확인해 승인하기 전에는 소스 아카이브를 다운로드하지 않는다.
4. 승인 후 아카이브를 OS Temp의 전용 경로에 다운로드하고 크기·파일 수·압축 경로를 검사한다. 아카이브의 모든 일반 파일은 GitHub commit tree의 blob SHA와 대조하고, 심볼릭 링크·submodule은 별도 검증 정책이 없으면 거부한다. GitHub가 별도 릴리스 해시나 서명을 제공하지 않는 경우 그 부재를 UI에 명시하고 이를 임의로 생성한 공식 서명으로 표현하지 않는다.
5. 새 버전에 대한 공식 파일 검증과 Dino Patch 호환성 검사를 분리한다. v0.5.54용 패치 연결부를 새 버전에 재사용하지 않는다.

## 적용·복구 조건

- LilacAnime가 실행 중이면 파일 교체를 시작하지 않고 사용자에게 종료를 안내한다. 앱 프로세스를 강제로 종료하지 않는다.
- 전체 공식 소스 파일 트리의 백업과 복원 테스트를 통과해야 한다. `DinoPatchManager`, 관리자 상태, 백업, 사용자 설정 및 알 수 없는 사용자 파일은 업데이트 대상에서 제외한다.
- 공식 파일의 현 해시가 마지막으로 검증된 원본과 다르면 덮어쓰지 않고 충돌로 중단한다. 새 버전에서 삭제된 파일도 이전 공식 파일이라는 근거와 현재 해시가 둘 다 맞을 때만 제거 후보가 된다.
- 업데이트는 동일 볼륨의 격리 staging과 트랜잭션 journal을 사용한다. 부분 실패 시 변경 전 파일을 전부 복원하고, 복원 결과 트리 해시가 일치하는지 재검사한다. 복원 검증이 실패하면 다음 파일 변경 작업을 잠그고 `상태 확인 필요`로 표시한다.
- 공식 소스 업데이트와 Dino Patch 적용은 별도 단계와 상태로 기록한다. 소스 업데이트 완료 뒤 패치 호환성이 입증되지 않으면 새 패치를 삽입하지 않는다. 안전한 전체 롤백이 검증되기 전에는 자동 업데이트를 활성화하지 않는다.

## 현재 지원 범위

`manager_core.preflight_official_source_update()`는 공식 최신 릴리스, 태그가 가리키는 commit/tree, 전체 Git tree, Windows 경로 안전성, 파일 수·크기, 고정 v0.5.54 기준 대비 추가·수정·삭제 파일 수를 읽기 전용으로 확인한다. 선택된 현재 원본이 있으면 현재 package 버전, 엄격한 패치 상태 지문, LilacAnime 실행 여부도 검사한다. 이 경로는 archive URL을 표시할 뿐 다운로드하지 않는다.

현재 v0.5.55는 공식 릴리스 페이지가 확인되지만, 패치 manifest는 v0.5.54에만 고정되어 있다. 따라서 `patchCompatibility=NOT_VERIFIED`, `rollbackCapability=NOT_PROVEN`, `sourceInstallEnabled=false`를 유지한다. `approve_official_update()`도 설치를 거부한다. NSIS 실행, 소스 폴더 변경, 새 버전 패치 재적용, 전체 소스 트랜잭션은 구현되어 있지 않다.

2026-10-31 읽기 전용 사전검사 결과: 공식 태그 `v0.5.55` → commit `207693ea7ee31b83276ac793b35136055a24de26` → tree `4aa940186722f7aa118fc4dcae843cc84023c84d`; 파일 145개, 합계 4,350,996 bytes, v0.5.54 대비 추가 4·수정 29·삭제 0개. GitHub 릴리스 API에서 배포 자산 5개를 확인했으며, 이들은 Windows/macOS/Linux 설치 앱용이고 소스 아카이브 자산은 없었다. 설치 자산에 연결된 SHA-256은 소스 아카이브의 무결성 증명이 아니다. GitHub 릴리스 자산에서 공식 소스 아카이브 서명/체크섬은 확인하지 못했다. 자체 비교 지문은 공식 서명으로 표시하지 않는다. 소스 archive는 다운로드하지 않았고, 공식 원본 파일도 교체하지 않았다. [공식 v0.5.55 릴리스](https://github.com/whispelyn-byte/LilacAnime-desktop/releases/tag/v0.5.55)

향후 설치 기능은 새 버전 소스 아카이브를 사용자가 승인한 뒤 OS Temp로 받는 것부터 시작해야 한다. 아카이브의 각 파일을 commit tree Git blob SHA-1과 대조하고, 전체 공식 소스 트리 백업·충돌 차단·트랜잭션 journal·실패 주입 및 강제 종료 후 복구를 별도 검증하기 전에는 설치 버튼을 활성화하지 않는다.
