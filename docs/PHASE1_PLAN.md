# Phase 1 — Windows 첫 시청 테스트 계획

## 목표

Windows에서 검색 → 작품 선택 → 회차 선택 → 허용된 영상 재생 → 로컬 이어보기 → 정확히 맞는 한국어 자막 자동 적용 → 수동 싱크 조정까지 한 흐름으로 확인한다. 사용자는 검색과 재생에 집중하고 앱은 기본 처리를 자동으로 한다.

Phase 1에서는 원본 LilacAnime를 전면 재작성하지 않는다. 기존 Electron 구조를 유지하면서 검증된 차이만 작게 고친다. 세부 상태와 근거는 FEATURE_GAP.md를 기준으로 한다.

## 시작 전 게이트

1. 원본 코드·이미지·폰트의 재사용 및 재배포 권한을 확인한다. 현재 원본 저장소는 GitHub 라이선스 null, 루트 LICENSE 부재, package.json MIT 선언 상태라 공개 배포 권리를 확정하지 않는다.
2. 사용할 실제 영상·자막 공급원의 이용 조건과 테스트 권한을 확인한다. 접근 제어·DRM 우회, 계정 쿠키 추출, 무단 다운로드는 전제하지 않는다.
3. 라이브 테스트는 허가가 확인된 자료에 한정한다. 권한이 확인되지 않으면 자체 소유/허가된 로컬 테스트 영상으로 플레이어·저장 흐름을 검증하고 외부 공급원은 미검증으로 남긴다.
4. 기존 사용자의 기본 LilacAnime 데이터는 건드리지 않는다. 앱 실행이 필요하면 별도 임시 userData 경로를 지원하는지 먼저 확인하고, 기존 프로필을 열지 않는다.

## 구현 순서

### 1. 새 저장소 기준 정리

- 새 앱의 표시 이름과 아이콘을 확정하기 전에는 제품명 변경을 넓히지 않는다. 저장소는 anime-player, 작업 폴더는 LilacAnime-Player다.
- 원본 LilacAnime 릴리스 주소를 제거했다. 현재 자체 릴리스 피드는 설정하지 않아 업데이트 검사·다운로드·변경 기록 조회가 비활성이다. 향후 피드가 승인되어도 확인·다운로드·설치는 각각 사용자가 선택하고, 앱 종료 때 자동 설치하지 않는다.
- README.md와 PRODUCT.md의 공급원 목록을 LinkAni 제외, 5개 지원 공급원으로 일치시켰다. README의 업스트림 설치 파일 링크·macOS 안내·TMDB 필수 주장·자동 업데이트 안내도 현재 비공개 Windows 개발 상태에 맞춰 고쳤다.

완료 조건: 새 저장소에서 앱 버전·폴더·업데이트 설정을 추적할 수 있고, 원본 릴리스를 새 앱 릴리스처럼 제안하지 않으며, README와 PRODUCT의 현재 지원 공급원이 일치한다. 완료했다. 자체 릴리스 배포 시에는 승인된 피드를 지정하고 테스트해야 한다.

### 2. 홈·검색·상세

- 보라·라일락 디자인과 기존 상세 화면을 보존한다.
- 홈의 핵심을 최신 회차, 요일별 방영표, 1~4분기 목록으로 재배치한다. 이어보기는 상단의 작은 레일, 즐겨찾기는 별도 메뉴로 둔다.
- 휴대폰이 아닌 Windows 우선 레이아웃으로 먼저 맞춘다. 날짜/요일 데이터가 없는 공급원은 임의로 방영일을 만들지 않는다.
- 한국어·일본어·영어 제목으로 5개 지원 공급원을 검색하고 시즌·극장판을 분리한다. AniList/MAL ID가 확정되지 않거나 연결이 모호한 후보는 통합하지 않는다.
- 자동완성과 최근 검색 기록은 입력을 방해하지 않는 범위에서 추가하고, 최근 기록 전체 삭제를 제공한다.

완료 조건: 세 언어의 검색어로 작품을 찾고, 다른 시즌·극장판을 잘못 합치지 않으며, 홈의 세 탐색 영역이 같은 작품 모델을 사용한다.

### 3. 회차 선택·재생·로컬 이어보기

- 기존 공급원별 상세·회차 경로와 서버 선택을 유지한다. 공급원을 합치는 과정에서 출처·회차 ID를 버리지 않는다.
- 실제 테스트 자산으로 선택 회차가 열리고 재생되는지 확인한다. 실패·네트워크 중단·잘못된 영상 응답은 성공으로 간주하지 않는다.
- 재생 위치를 로컬 저장하고 앱 종료·재실행 뒤 해당 회차와 위치를 복구한다. 95% 이상 시 처음부터 시작하는 기존 규칙은 사용자 선택 흐름과 함께 확인한다.
- 회차 종료 후에는 완료 표시와 다음 화 보기 버튼만 표시한다. playerAutoPlay의 새 사용자 기본값을 false로 두며, 기존 설정 마이그레이션도 실제 확인한다.
- 재시도 횟수를 제한한다. 서버 자동 전환은 같은 작품·회차가 확인되고 원래 위치를 복구할 수 있을 때만 수행한다. 전환 실패 후에는 한 번의 간단한 안내를 보여 준다.

완료 조건: 허가된 자산 한 회차에서 재생·진행률 저장·재실행 후 이어보기를 확인하고, 종료 뒤 다음 화가 저절로 시작하지 않는다.

### 4. 한국어 자막 자동 탐색

- 현재 재생 회차의 내장 트랙과 온라인 한국어 자막을 출처별로 보존한다. 후보 상태는 회차 단위로 연결하고 제작자/출처를 알 수 있게 유지한다.
- 우선순위는 코드에 하드코딩하기 전에 기존 동작을 표로 고정한다. 회차·시즌·영상판이 확실할 때만 자동 적용하고, 동률·불확실한 후보는 목록에서 직접 선택하게 한다.
- 검색 결과 없음과 네트워크/API 오류를 다른 상태로 처리한다. 오류를 자막 없음으로 간주해 번역 단계로 넘어가지 않는다.
- SRT, SMI, ASS, SSA, VTT의 실제 샘플을 분리해 확인한다. ASS/SSA 원본 렌더와 일반 자막의 자동 배치를 구별한다.
- 수동 싱크 조절과 저장값 복귀를 확인한다. 음성·문장 비교 기반 자동 싱크는 이번 단계 범위 밖이다.

완료 조건: 맞는 한국어 자막은 자동 적용되고, 다른 회차 후보는 자동 적용되지 않으며, 사용자가 출처를 선택하거나 검색 오류를 이해할 수 있다.

### 5. Windows 패키지·회귀 확인

- 수정 뒤 오프라인 테스트를 실행하고, 실제 서비스 확인 결과는 별도 체크리스트로 기록한다.
- 실제 설치/앱 실행 확인은 기본 사용자 데이터 대신 분리된 임시 프로필에서 한다.
- 로컬 로그에 API 키, 인증 정보, subtitle 원문, 시청 기록을 넣지 않는다. 외부로 진단자료를 자동 전송하지 않는다.
- 코드서명·공개 릴리스·최종 배포 채널은 이번 Phase 1의 완료 조건이 아니다.

## Phase 1에서 하지 않는 작업

- Android 앱과 기기간 클라우드 동기화
- 이메일·Google 로그인과 멀티 프로필
- 로컬 AI 번역 고도화, API 없는 ChatGPT 자동 번역
- 일본어 음성/자막 의미 비교 자동 싱크
- 다운로드 기능 확장
- 자막 문장 편집기, 다음 화 자동 재생, 외부 공급원 플러그인
- 공개 배포, 설치/포터블 선택 확정, 자동 업데이트 활성화

## 검증 기록 형식

각 확인은 실제 실행 명령 또는 입력 자료, 기대 결과, 관찰 결과, PASS/FAIL/미검증, 실행 환경을 기록한다. 모의·loopback 테스트는 실제 사이트 재생 증거와 분리한다.

## 2026-10-09 로컬 Phase 1 스모크 테스트

- 환경: Windows의 Electron 소스 앱, 임시 `userData`/`sessionData`, 외부 DNS 차단. 기존 사용자 프로필과 공급원 사이트는 사용하지 않았다. 12초 H.264 합성 MP4와 두 큐짜리 합성 WebVTT를 입력했다.
- 재생·이어보기 기대 결과: 재생 중 진행률 저장, 앱 재시작 후 같은 회차 위치 복구. 관찰 결과: 3.40초에서 일시 정지했을 때 28% 저장, 앱 재시작 후 저장값 28%를 읽고 3.36초로 seek. **PASS — 로컬 재생·이어보기**.
- 자막 기대 결과: ChatGPT 수동 번역 프롬프트를 만들고 결과를 회차별로 저장·적용하며 원래 시간코드를 유지. 관찰 결과: 클립보드·외부 브라우저 대체 함수로 복사/열기를 확인하고 한국어 결과 두 줄을 저장했으며, 1.25초에서 `안녕하세요` 큐가 활성화됐다. 두 큐의 원래 시간코드가 보존됐다. **PASS — 로컬 자막 흐름**. 실제 ChatGPT 왕복은 미검증.
- 회차 종료 기대 결과: 현재 회차를 100% 완료로 저장하고 다음 화를 자동 재생하지 않음. 관찰 결과: `다음 화는 직접 선택해 주세요.` 안내, 다음 화 버튼 활성, 영상 주소와 회차는 그대로, 진행률 100%. **PASS — 수동 다음 화 조건**.
- 범위 제한: 공급원 검색·상세·영상·온라인 자막의 실제 응답과 설치된 NSIS 앱 창은 이 스모크 테스트로 검증하지 않았다. 테스트 임시 폴더 `%TEMP%\lilac-smoke-00ad878206974f2bacbb10c1213336e9`는 실행 정책이 재귀 삭제를 차단해 남아 있다.

## 2026-10-09 검색·회차 UI 스모크 테스트

- 환경: Windows Electron 소스 앱의 자체 DevTools, 임시 `userData`·`sessionData`, 외부 DNS 차단. `provider:catalog`·`provider:detail`·`provider:resolve`와 자막·설정 IPC를 결정적 합성 응답으로 대체했다. 검색 결과는 합성 작품 1개와 회차 2개, 영상은 앞 스모크 테스트에서 만든 12초 로컬 MP4다. 실제 공급원 사이트·계정·사용자 프로필은 사용하지 않았다.
- 동작: 앱의 검색 입력에 `테스트 애니`를 입력하고 Enter → 결과 카드 클릭 → 작품 상세에서 1·2화 확인 → 1화 선택. 한국어 작품 카드·상세 제목과 회차 2개가 표시되고, `provider:resolve`가 선택한 1화를 받았으며, 로컬 영상 `readyState=4`, 길이 12초를 확인했다. 시청 기록에도 RE:Anime 공급원·1화가 저장됐다. **PASS — 모의 공급원 UI·IPC 경로**.
- 렌더러 예외 0건, 외부 HTTP(S) 요청 0건. 이어보기 카드의 진행률 요소와 직접 회차 라벨도 재생 중 갱신됐다. 첫 실행에서 발견한 카탈로그 필터 스크립트의 전역 `$` 초기화 순서 문제와 이어보기 카드의 잘못된 progress HTML을 고쳤다.
- 검증 한계: 공급원 응답은 모두 합성값이다. 실제 사이트 검색·상세·영상·자막 응답, 재시작 이어보기 및 설치 앱의 화면은 확인하지 않았다. 임시 스모크 파일은 `%TEMP%\lilac-smoke-00ad878206974f2bacbb10c1213336e9` 아래에 있다.

## 2026-10-09 한국어 자막·수동 싱크 스모크 테스트

- 환경: 앞선 검색 UI 테스트와 같은 격리 Electron 소스 앱·임시 프로필·외부 DNS 차단을 사용했다. 검색·상세·회차·자막 IPC는 합성 응답이며 12초 로컬 MP4와 합성 한국어 WebVTT를 썼다.
- 동작: 검색 결과에서 작품 상세를 열고 1화를 재생했다. RE:Anime 한국어 트랙이 자동 적용되고 `한국어 합성 자막` 큐가 활성화됐다. 플레이어 설정을 열고 `자막 모양` 탭의 싱크 입력을 `500`으로 바꾼 뒤 확정하자 로컬 저장값 `500`, 화면 레이블 `+0.50초 (늦게)`, 현재 자막 타이밍 보정이 확인됐다. **PASS — 합성 한국어 트랙·플레이어 싱크 UI**.
- 결과: 검색부터 합성 영상·자막·싱크까지 11개 조건 통과, 렌더러 예외 0건, 외부 HTTP(S) 요청 0건. 사용한 테스트 UI의 실제 이벤트는 숫자 입력 확정의 `change`였다. 숨겨진 설정 페이지 요소에 `input` 이벤트만 보낸 첫 점검은 앱 결함을 뜻하지 않았으며, 실제 플레이어 설정 패널 조작으로 다시 검증했다. 회귀 방지를 위해 두 설정 화면의 `change` 저장을 테스트에 추가했다.
- 검증 한계: 한국어 자막 파일과 회차·시즌·영상판의 실제 공급원 일치, 허가된 외부 영상 재생, 실제 자막 타이밍 체감, 설치 앱 창의 화면은 미검증이다. 임시 스모크 파일은 `%TEMP%\lilac-smoke-00ad878206974f2bacbb10c1213336e9` 아래에 있다. 변경 후 전체 `node --test`는 76/76 통과했다.

## 2026-10-09 업데이트 원본 차단
