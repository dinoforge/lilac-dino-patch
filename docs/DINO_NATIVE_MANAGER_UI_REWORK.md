# DinoPatch Beta 8 — Rust 네이티브 관리자 UI 개선

기준 브랜치: `feature/dino-beta8-345-11-12-15-20261114`  
작업 브랜치: `feature/dino-beta8-rust-manager-ui-20261114`

**범위:** `tools/dino-patch-manager/native-rust/src/gui.rs`의 화면 표시·경로 입력 상태·버튼 활성화 조건을 개선했습니다.
기존 `transaction.rs` 패치·백업·원복 엔진, 패치 대상 원본 ASAR 및 이전 Beta 8 EXE는 변경하지 않았습니다.

## 화면 구성

1. 현재 패치 상태: 3단계 안내, 상태 배지, 다음 할 작업, 자동 감시 여부.
2. 현재 진단: 긴 오류/사유 문자열을 전체 행에 표시하고 충돌·비호환일 때 보호 조치를 명시.
3. 설치 원본: 버전, 원본 경로, 폴더 변경, 임시 경로 입력.
4. 패치 목록: 설치 상태와 자동 감시 활성화 여부.
5. **고급 관리 열기:** 수동 검사·적용·해제, 백업·원복, 작업 로그, 원본 앱과 DinoPatch 릴리스 페이지. 기본 상태에서는 접혀 있습니다.

## 작은 화면

최소 창 크기를 **640×560**으로 변경했습니다. 설치 원본 카드 폭이 720px 미만이면
버전과 설치 경로를 세로 방향으로 배치하고, 길게 잘린 경로는 마우스를 올렸을 때 전체를 볼 수 있습니다.
긴 진단 문구는 배지와 한 줄에 배치하지 않고 전체 카드 너비에 표시합니다.

## 설치 경로 변경 보호

- `경로 직접 입력`을 누르면 `path_draft`에 현재 경로를 복사합니다.
- **입력 중에는 관리자의 활성 원본 경로(`root`)가 바뀌지 않습니다.**
- `입력 취소`를 누르면 초안만 폐기합니다.
- `경로 검사`를 누른 경우에만 경로를 확정하고 상태를 검사합니다. 원본 경로가 바뀌면 이전 백업 ID 표시를 폐기합니다.
- 경로 입력 자체는 파일을 수정하지 않습니다. 다만 **자동 감시가 켜진 경우 검사 후 기존 정책에 따라 자동 패치가 수행될 수 있습니다.** 반드시 설치 복사본으로 실사용 검증을 진행하세요.

## 안전한 버튼 노출

- 수동 패치 적용은 `UNPATCHED` 또는 `ALREADY_UNPATCHED` 상태에서만 활성화됩니다.
- 해제와 백업 복원은 `APPLIED` 또는 `ALREADY_APPLIED` 상태에서만 활성화됩니다. 백업 복원에는 비어 있지 않은 백업 ID도 필요합니다.
- 최종 적용·원복·복구 작업은 기존 확인 대화상자를 거칩니다. 이 화면 조건은 1차 필터이며, **실제 SHA-256 확인 및 구조 검사 권한은 `transaction.rs`에서 계속 검증합니다.**
- 백엔드 작업 실패·스레드 중단·충돌 안내 시 작업 기록을 볼 수 있도록 고급 관리 메뉴를 엽니다.
- 상태를 알 수 없을 때 원본이 전혀 변경되지 않았다고 단정하지 않습니다.

## Windows 수동 검증 항목

- 640×560/940×840 양쪽 창 크기에서 원본 경로, 버튼, 진단 문구 가림 여부
- 직접 경로 입력 중 프로그램 원본 경로가 바뀌지 않는지, 취소 시 그대로인지
- 위험 상태에서 수동 적용·해제·복원이 비활성화되는지
- 적용/원복 확인 대화상자와 실패 시 고급 관리·진단 로그가 보이는지
- 자동 감시 켠 상태에서 새 경로 검사 뒤 예상하지 못한 원본 변경이 발생하지 않는지
- 기존 공식 앱과 DinoPatch 릴리스 버튼이 페이지 열기만 수행하는지

정식 릴리스 표시는 **Windows 실제 실행과 설치 복사본 테스트가 완료된 후** 검토합니다.


## 글자 가독성 보완 (후속 수정)

일부 화면에서 글자가 흐리거나 작게 보이는 문제를 줄이기 위해 Rust GUI에 다음 기능을 추가했습니다.

- 상단의 **글자 크기**에서 **기본 100%, 크게 120%, 매우 크게 140%**를 즉시 선택할 수 있습니다.
- egui 공식 줌 API를 사용해 글자뿐 아니라 버튼·패널도 함께 확대합니다. Windows DPI 배율에 맞춰 작동하며 확대 상태는 이 실행에만 유지됩니다.
- 카드에 쓰이는 보조 텍스트 색상을 밝게 변경하고, 레이블·상태 배지·진단 문구·작업 로그의 기본 표시 크기를 키웠습니다.
- 긴 상태 배지와 패치 목록의 텍스트는 폭이 좁거나 확대되어도 행을 넘겨 배치할 수 있도록 수정했습니다.
- Windows 시스템 한글 글꼴을 `malgun.ttf`, `malgunbd.ttf`, `malgunsl.ttf` 순서로 조회합니다. 시스템에 없는 글꼴을 외부에서 내려받거나 포함하지 않습니다.
- Windows 시스템 한글 글꼴을 모두 찾지 못하면 진단 로그에 남깁니다. 이 경우 기본 폰트만으로 한글이 표시된다고 보장하지 않습니다.

## UI 설정 재시작 보존 및 검증 준비 (2026-11-14)

- Rust `eframe 0.33`에 `persistence` 기능을 활성화했습니다.
- 글자 크기 **100% / 120% / 140%**, 고급 관리 메뉴의 접힘 상태, 기본 창 크기/위치가 재시작 후에도 복원되도록 연결했습니다.
- 저장된 확대율 값은 0~2 범위로 검증하며 손상되었을 경우 기본 100%로 초기화합니다.
- **설치 경로, 입력 중인 경로, 백업 ID, 자동 패치 정책, 사용자 데이터는 UI 설정 저장 대상에서 제외**했습니다. egui 편집기 내부 상태의 자동 저장도 해제했습니다.
- Windows GUI CI 스모크 테스트에서 `APPDATA`와 `LOCALAPPDATA`를 각각 테스트 전용 경로로 격리합니다.
- 이전 문단의 "확대 상태는 이 실행에만 유지"는 당시 구현에 대한 기록입니다. **이 브랜치부터 확대율이 다음 실행에도 유지됩니다.**
- UI 계약 검사 **19개를 별도 JavaScript 실행 환경에서 재현하여 모두 통과**했습니다. 이 검사는 실제 Node.js, Rust 컴파일 또는 Windows 실행 검증을 대신하지 않습니다.

## 2026-11-14 작업 단계 및 백업 목록·복원 UI

작업 브랜치 `feature/dino-beta8-manager-progress-backup-ui`에서 Rust 관리자 화면을 보강했습니다.
기존 `transaction.rs`의 패치·백업·복원 검증과 자동 감시 정책은 변경하지 않았습니다.

- 작업 요청, 실제 엔진 단계, 결과 상태 재검증을 별도 작업 스레드 이벤트로 표시합니다. 측정할 수 없는 퍼센트 진행률은 표시하지 않습니다.
- 작업 성공·오류·패닉·응답 채널 종료 시 busy 상태를 해제하고, 오류에서는 진단 로그를 펼칩니다. 설치 경로와 세대 번호가 달라진 이전 작업 응답은 무시합니다.
- 백업 조회는 작업 스레드에서 `transaction::backups()`를 호출합니다. 화면은 엔진이 반환한 ID·버전·생성 시각·복원 가능 여부만 보여 줍니다. 현재 엔진 API는 현재 설치 버전의 상태만 반환하며, 여러 버전 백업을 검색하지 않습니다.
- 사용자가 고른 복원 가능 백업의 ID만 엔진에 전달합니다. `APPLIED` 상태 및 `restorable` 검사를 거쳐야 복원 요청이 가능하고, 확인창에 경로·현재 버전·백업 버전·ID를 표시합니다. 취소는 파일 작업을 시작하지 않습니다. 실제 경로·버전·SHA-256 검증은 계속 엔진이 수행합니다.
- 설치 경로를 바꾸면 백업 목록·선택과 오래된 작업 응답을 무효화합니다. 백업 조회 실패는 빈 목록으로 숨기지 않고 오류 및 진단 로그로 알립니다.

### Windows GUI 점검 범위와 제한

새 GUI EXE를 격리된 LilacAnime v0.5.65 설치 사본과 전용 `APPDATA`, `LOCALAPPDATA`, `TEMP`로 시작했습니다. 940×840 관리자 창과 버전 인식·자동 적용 표시까지 확인했습니다. 화면 제어 중 대상 창과 다른 브라우저 화면이 반환되어 상호작용을 중단했으므로, 백업 목록의 0/1/복수 표시, 확인창 취소·승인, 크기·확대율 및 재시작 보존은 실제 GUI에서 확인하지 못했습니다. GUI 창의 자동 적용 완료 표시만으로 전체 UI 검증을 완료 처리하지 않았습니다.

격리 설치 사본은 이후 CLI 엔진으로 복원했습니다. 최종 `resources/app.asar` SHA-256 `9A5BBCDDDA592F173D6E1C5BC01AC0BBBEC8D003C40CB3A4113AFB307A08DA12`가 공식 원본과 일치하고 `inspect`는 `UNPATCHED`를 반환했습니다. 백업 ASAR 및 상태 기록 파일은 격리 경로에 남아 있음을 확인했습니다. 해제 후 현재 엔진의 `backups()` 응답이 빈 목록인 것은 기존 API가 활성 상태 기록만 열거하기 때문입니다.

GitHub Actions는 실행하지 않았습니다. 원격에서 활성화된 워크플로는 수동 실행·태그·릴리즈 이벤트만 사용하고, 브랜치 푸시 워크플로는 비활성 상태임을 확인했습니다. A32/기존 배포본·실제 사용자 설치본·실제 사용자 프로필은 변경하지 않았습니다. 실제 GUI 백업 조작 검증은 남아 있습니다.
