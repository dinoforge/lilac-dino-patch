# DinoPatch Beta 8 — 다국어 검색, 회차 전환, SQLite 복원 (2·3·4)

## 2. 다국어 작품 검색

- 한국어·영어·일본어(한자/가나) 별칭을 여러 개 보유한 작품에서 검색
  호출 수(기본 3개, 상세 5개)가 한국어 별칭에만 소진되지 않게
  언어별 검색어를 번갈아 선택합니다.
- 통합 검색 화면의 별칭 검색에서도 이미 저장된 공식/사용자 제목과
  영어·일본어 표기, 작품의 다른 이름을 검색어 후보에 포함합니다.
- 제목만 같은 작품을 자동 합치지 않습니다. 작품 외부 ID, 방영 연도,
  시즌·형식 검증과 기존 수동 분리 기록을 그대로 적용합니다.
- 단순 검색어 후보 변경이며 특정 공급원이 모든 작품을 제공한다는
  보장은 아닙니다.

## 3. 동일 회차 재생 공급원 전환

- 원래 작품과 연결 검증된 공급원에서만 대체 회차를 탐색합니다.
- 같은 번호·더빙 유형의 회차가 **정확히 한 개**일 때만 후보로
  선택합니다. 같은 화수가 두 개(서로 다른 편집본 등)면 자동으로
  고르지 않습니다.
- 상세 결과의 공급원 ID와 작품 ID가 기대한 대상과 다르면
  후보를 차단합니다.
- 후보 영상 스트림의 주소를 확인한 다음에만 플레이어 전환을
  시작합니다. 조회 실패 시 원래 재생 컨텍스트를 유지합니다.
- 사용자가 전환을 선택한 뒤 기존 재생 위치(초)와 회차 번호를
  보존합니다. 전환 이후의 스트리밍 네트워크 오류를 모두 예방하는
  것은 아니며 기존 앱의 재생 복구 로직은 변경하지 않습니다.

## 4. SQLite 기록 유지

- 로컬 캐시가 최신으로 보이더라도 한 번은 SQLite의 정확한
  공급원 ID를 조회하여 **DB에서 확정한 연결·분리 기록과
  공통 제목**을 복원합니다.
- SQLite의 첫 페이지(최근 180개) 밖에 있는 작품도 해당 공급원을
  다시 방문할 때 복원하며, 이미 확인한 ID는 불필요하게 반복
  조회하지 않습니다.
- 로컬 편집 내역이 SQLite 저장 대기 중이면 DB 조회 전에 먼저
  저장하여 최신 제목이 오래된 기록에 덮이지 않게 합니다.
- 직접 바꾼 한국어 제목은 같은 밀리초에서 연속 편집하더라도
  수정 시각이 증가하게 기록합니다. SQLite에서는 시각이 동일한
  오래된 캐시 제목이 기존 수동 제목을 덮어쓰지 못하게 합니다.
- 제목 저장/자동 제목 전환 뒤에는 SQLite flush를 즉시 요청합니다.
  SQLite 사용이 불가능하면 기존 로컬 캐시는 그대로 보존합니다.
- 공식 LilacAnime 설정, 기본 제목 캐시, 재생 기록, 기존 백업 및
  사용자 DB 파일을 삭제/초기화하는 코드가 없습니다.

## 검증 범위

대상 브랜치의 단위 시나리오에 다음 항목을 추가했습니다.

- 한글 별칭이 많아도 영어/일본어 검색어가 선택됨
- 중복·스페셜·다른 공급원의 동일 화수 후보 차단
- 영상 주소 사전 확인 실패 시 기존 플레이어 유지
- 단 하나의 호환 회차에서 재생 위치 유지
- 수동 제목 변경 시 단조 증가하는 수정 시각
- 오래된 로컬 캐시에서 SQLite의 5개 공급원과 제목 복원
- SQLite 재시작 후에도 수동 제목 유지 및 동일 시각 충돌 차단

변경 소스의 문법·선택 테스트 및 인메모리 SQLite 어댑터 경로를
검증했습니다. 실제 Windows LilacAnime v0.5.65 설치본에서
전체 검색·재생·SQLite 재시작을 끝까지 검증한 것은 아닙니다.
**GitHub Actions CI 및 Windows EXE 재빌드는 실행하지 않았습니다.**
