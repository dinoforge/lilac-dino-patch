# DinoPatch: 버전 번호 무관 자동 호환성 검사

## 핵심 원칙

DinoPatch의 적용 가능 여부는 사전에 등록한 LilacAnime 버전 번호로 판단하지
않습니다. 설치된 `resources/app.asar`를 직접 검사해 다음 조건을 만족하면
새 버전도 동일한 패치 엔진으로 처리합니다.

- `package.json`의 LilacAnime 앱 식별자가 일치할 것
- `src/app.js`, `src/index.html`, `src/player.js`, `electron/main.cjs`,
  `electron/preload.cjs`가 유효한 일반 ASAR 파일로 읽힐 것
- 공식 파일에 추가하는 **7개 연결 지점**이 사용 가능한 프로필 중 하나에 대해
  각각 정확히 한 번 존재할 것
- 기존 DinoPatch 런타임 모듈이 이중 삽입되지 않을 것
- 내장 모듈 5개의 manifest SHA-256과 실제 내용이 일치할 것
- 설치 파일과 기존 백업의 SHA-256 검사, 사용자 앱 프로세스 종료 검사,
  pending 기록·임시 파일 안전 검사가 모두 통과할 것

조건을 만족하지 않는 새로운 공식 버전에는 아무것도 쓰지 않습니다.
숫자가 새 버전이라도 구조가 같으면 통과하고, 구버전이라도 구조가 다르면
차단합니다. 제목·검색·재생 등 실제 동작의 완전한 호환까지 보장한다는 뜻은
아니므로 공식 업데이트 후 테스트용 설치본에서 먼저 재생을 확인합니다.

## 공식 앱 업데이트 후 백업 관리

DinoPatch의 이전 `state.json`이 v0.5.64, 상태가 `UNPATCHED`이고
현재 설치본이 v0.5.65인 상황을 예로 듭니다.

1. 이전 상태 기록이 정상이고 이전 `original-app.asar`의 SHA-256이 일치하는지 확인합니다.
2. 새 v0.5.65 ASAR의 식별자와 연결 지점 7개를 검사합니다.
3. 조건이 모두 맞으면 **이전 `state.json`과 `original-app.asar`를 그대로 보존**합니다.
4. 사용자가 수동 적용을 선택하면 새 버전 전용 `original-<버전 해시>.asar`를 먼저 백업하고 검증합니다.
5. 패치 전 `pending.json`을 기록하고 새 ASAR를 적용한 뒤 교체된 파일의 해시를 확인합니다.
6. 새 상태는 `state-<버전 해시>.json`에 별도로 기록됩니다.
7. 새 버전의 패치 해제는 **새 버전 전용 백업**만 사용하며, 과거 v0.5.64 백업을 현재 버전으로 복원하지 않습니다.

사용자가 과거에 직접 패치를 해제한 상태는 새로운 공식 버전에서도
**수동 적용**이 필요합니다. 이전 상태가 `APPLIED`였으나 공식 업데이트가
패치본을 새 원본으로 교체한 경우에는 정상 구조 검증 후 재적용할 수 있습니다.

중단되면 임시 파일과 `pending.json`을 삭제하지 마세요. 새 버전
`pending.json`의 원본/패치 해시를 검증한 뒤 복구 기록을 정리합니다.

## 확인된 공식 소스

2026-11-13에 공개된 공식 LilacAnime v0.5.65 소스에서는
기존 패치 프로필의 7개 연결 지점이 각각 한 번 존재하는 것을 확인했습니다.
이 사실은 소스 구조 호환 가능성만 확인한 것이며, 모든 실제 설치본이 동일하다고
가정하지 않습니다. Rust 구조 검사가 사용자 설치본에서 다시 수행됩니다.

## 남은 실기기 검증

- 업데이트된 v0.5.65 실제 설치본에 대한 새 EXE 적용
- 재실행 시 앱 정상 시작 및 공급원·SQLite 데이터 보존
- 새 버전 백업을 이용한 패치 해제와 원본 해시 확인
- 전원 중단·충돌 상태에서 pending 복구 확인
