# LilacAnime 기반 Windows → Android 애니메이션 앱 개발 계획

> 작성 목적: 사용자와 합의한 1~42번 조건을 Codex가 빠뜨리지 않고 단계적으로 구현하도록 하는 기준 문서.
> 상태: **계획 초안**. Codex 실행, 저장소 수정, 배포는 아직 수행하지 않음.
> 원본: https://github.com/whispelyn-byte/LilacAnime-desktop
> 방향: **기능은 내부에서 자동으로 처리하고, 사용자는 검색 → 작품 선택 → 재생만으로 편하게 시청.**

## 1. 최상위 원칙

1. Windows를 우선 개발하고, 검색·재생·자막·이어보기를 실제 영상 환경에서 검증한 뒤 Android로 확장한다. Electron 프로젝트가 Android APK로 바로 변환된다고 전제하지 않는다.
2. 원본 LilacAnime의 잘 동작하는 구현과 보라색 계열 디자인을 가능한 한 유지한다. 전면 재작성은 금지하며, 필요하다고 판단되는 모듈만 리팩터링한다.
3. 사용자가 보는 화면은 깔끔한 OTT 형태로 유지하고, 대부분의 설정과 오류 복구는 자동 처리한다. 기존 기능이라도 합의된 사용자 경험에 반하면 조정한다.
4. 합의한 최종 기능과 **첫 번째 테스트 버전에 들어가는 기능을 구분**한다. 미구현 기능을 이미 동작하는 것처럼 안내하지 않는다.
5. 공급원·자막·다운로드는 권한이 있거나 이용 조건에서 허용되는 범위에서만 연결한다. DRM 또는 접근 권한을 우회하지 않는다. 원본 코드·이미지·서체 등 재사용·재배포 권한과 고지 의무를 확인한다.
6. 계정 토큰, 암호, 자막 원문, 사용자의 시청 기록 등 민감 정보의 로그 유출을 방지한다. 오류 기록은 기본 로컬 저장, 사용자 명시 선택 시에만 공유한다.
7. 불명확하거나 불가능한 기능은 숨기지 말고 **검증 필요**, **조건부 지원**, **미지원** 등으로 정확히 분류한다.

## 2. 확정 요구사항 (1~42번)

### 플랫폼과 핵심 탐색 (1~5)
1. Windows 독립 실행형 데스크톱 앱을 먼저 개발하고 Android 앱으로 확장한다. Chrome 확장·macOS·iOS는 이번 범위에서 제외한다.
2. LilacAnime의 기존 다중 공급원 구조를 최대한 유지한다(Re:Anime, Miruro, Animenosub, 애니24, Linkkf). 현재 사용 가능 여부 및 권한은 공급원별 검증한다. LinkAni는 이후 사용자 결정으로 지원 대상에서 제외했다.
3. 보라·라일락 디자인을 유지한다. 홈 기본 콘텐츠는 최신 회차, 요일별 방영표, 분기별 목록. 사용자 맞춤 이어보기는 상단에 작은 영역으로 추가한다.
4. 한국어 제목은 TMDB → AniList → Wikidata 순으로 조회하고 실패 시 원제를 사용한다. 한국어·일본어·영어 검색을 지원하되, 서로 다른 시즌/판본을 잘못 합치지 않는다.
5. 한국어 자막을 자동 검색·적용한다(내장 트랙, Kairan, Csora, Anissia 등록 제작자 블로그, 사용자 파일 등). 작품·시즌·회차 및 영상판이 확실히 일치할 때만 자동 적용하고, 애매하면 사용자가 선택한다.

### 번역·싱크·자막·재생·다운로드 (6~10)
6. 우선적으로 로컬 AI 자동 번역을 지원하고, 사용자가 ChatGPT를 이용해 수동으로 번역·가져오는 흐름을 지원한다. **API 키 없는 ChatGPT 자동 번역**은 사용자가 원하는 목표이지만 공식적으로 지원·허용되는 안정적인 방법의 존재가 확인되지 않았으므로 별도 기술·약관 검증 항목으로 보류한다. 동의받지 않은 쿠키 추출/계정 자동화나 우회 방식은 구현 전제에 넣지 않는다. 유료 번역 API의 사용을 필수 요건으로 삼지 않는다.
7. 일본어 음성 인식과 자막 문장의 의미 비교를 바탕으로 자동 싱크한다. 검증된 구간에만 적용하고, 사용자 수동 보정 우선권 및 되돌리기를 제공한다. 단순 무음 탐지만으로 정확한 싱크라고 주장하지 않는다.
8. SRT, SMI, ASS, SSA, VTT를 지원하며 ASS/SSA의 색, 글꼴, 배치, 효과를 최대한 보존한다. 잘리는 경우에만 자동 조정하고 수동 설정도 지원한다.
9. 원본 플레이어의 재생, 탐색, 전체 화면, 품질/속도, 자막, OP/ED 건너뛰기, 이어보기, 서버 선택, 플랫폼별 단축 조작을 최대한 보존한다. 단, 합의한 '다음 화 수동 시작' 등 UX 조건이 우선한다.
10. 허용된 콘텐츠의 개별/일괄 다운로드, 일시정지·재시도, 저장 위치 관리, 자막 포함 오프라인 시청을 지원한다.

### 계정·설정·공급원·검색 통합 (11~18)
11. 기기 로컬 기록 유지와 함께 시청 기록·이어보기·즐겨찾기·설정·프로필의 Windows/Android 자동 동기화를 지원한다. 영상 파일 자체는 동기화하지 않는다.
12. 설정 및 기록 자동 백업과 새 버전 알림을 제공한다. 실제 업데이트 설치는 사용자가 선택한다. 수동 백업 내보내기·가져오기와 복구도 지원한다.
13. 관리형 클라우드 기반 계정 및 동기화 방식을 사용한다. Supabase/Firebase는 비교 후보이지 서비스 확정은 아니다. 무료 한도, 비용, 권한, 개인정보를 검토한다.
14. 이메일·비밀번호 및 Google 로그인 모두 제공하고, 한 사용자 계정에 안전하게 연결할 수 있도록 한다.
15. 기본 멀티 프로필만 제공한다. 게스트 모드, 프로필 PIN, 자녀용 프로필은 제외한다.
16. 새 공급원은 개발자가 앱 업데이트로 지원한다. 사용자가 임의의 외부 공급원 확장/저장소를 설치하는 구조는 만들지 않는다.
17. 같은 작품은 통합 카드로 보여 주되, 상세 화면에서 공급원과 서버를 선택할 수 있다. 공급원별 필터도 제공하고 불확실한 매칭은 합치지 않는다.
18. 사용자 선호 공급원/서버를 기억하고 우선 적용한다. 재생 실패 시 조건에 맞는 다른 서버로 자동 전환하며, 재생 위치·자막·싱크를 점검한다.

### 자막 상세 동작·프로필·다운로드 (19~27)
19. **한국어 자막 검색을 충분히 완료한 뒤** 적합한 결과가 없는 것으로 판명되면 일본어/영어 자막으로 번역을 시작한다. 검색 서비스 오류는 '자막 없음'과 구별한다. 캐시가 있으면 재사용한다.
20. 빠른 로컬 AI 번역을 먼저 표시하되, 번역 품질을 검증하고 문제가 있는 문장만 다시 처리한다. 작품별 인명·용어집을 유지하고 회차별 결과를 저장한다.
21. 음성·문장 기반 싱크는 필요한 구간부터 빠르게 분석하면서 여러 문장으로 검증한 다음 보정한다. 신뢰도가 부족하면 보정하지 않는다. 영상 버전별 캐시를 쓴다.
22. 원본 자막 스타일이 기본이고, 사용자가 원하는 경우에만 크기·글꼴·색상·위치 등을 바꾼다. 원본으로 복귀 가능하며 프로필별 설정을 동기화한다.
23. 자막 선택 시 정확한 시즌·회차, 영상판 호환성, 선호 제작자, 싱크 검증 결과를 종합한다. 비슷한 후보는 직접 선택하게 한다.
24. **자막 편집기 제외**. 자막 문장/타임라인을 편집하는 별도 도구를 만들지 않는다. 이미 확정한 간단한 수동 싱크 조절은 유지한다.
25. 다운로드 버튼 하나로 영상·자막을 자동 정리하고 오프라인 보관함에서 바로 재생한다. 복잡한 파일 관리 설정은 기본 UI에 드러내지 않는다.
26. 즐겨찾기 작품의 새 회차는 앱 내부에 `NEW` 표시만 한다. 별도의 시스템 푸시 알림은 제공하지 않는다.
27. 이어보기는 마지막 위치에서 자동 시작하며, 사용자가 선택하면 처음부터 볼 수 있다. Windows/Android 간 위치 동기화도 적용한다.

### 홈·OTT 플레이어·오류 처리 (28~39)
28. 한 회차가 끝나면 시청 완료 처리 후 `다음 화 보기` 버튼을 표시한다. **다음 화 자동 재생은 하지 않는다.**
29. 홈 상단에는 간단한 최근 이어보기 목록, 즐겨찾기는 별도 메뉴에 둔다.
30. 검색 자동완성과 최근 검색어를 제공한다. 최근 검색 기록 삭제 기능 포함.
31. 상세 화면은 포스터·한국어 제목·줄거리·평점·방영 정보·큰 재생 버튼·시즌/회차 목록 중심의 간결한 OTT 스타일. 공급원 선택은 필요할 때 표시한다.
32. 재생 중 조작 UI는 숨기고 마우스 이동/터치 때만 노출한다. 기본 버튼 외의 화질·속도·서버·싱크는 통합 설정 메뉴에 둔다.
33. 자막 검색·번역·싱크 진행 중 작은 상태 메시지만 표시하며, 실패하면 간단한 재시도 안내를 제공한다.
34. 재생 오류는 자동 재시도→대체 서버를 우선 시도하고, 실패 시에만 사용자에게 알린다. 무한 재시도는 하지 않는다.
35. Windows는 마우스·키보드, Android는 터치·간단한 제스처. 기능은 일관되게 유지하되 조작은 기기 친화적으로 제공한다.
36. 기본 원본 화면 비율 유지, 버튼 한 번으로 화면 채우기/원상 복귀. Android 가로 전체 화면 지원. 영상/자막 잘림에 주의한다.
37. 로그인 상태를 안전하게 유지하고 앱 실행 시 마지막 프로필의 홈 화면으로 곧바로 진입한다. 프로필 변경과 로그아웃 가능.
38. 최초 실행에는 로그인·프로필 생성만 필수로 하고 나머지는 자동 기본 설정한다. 로컬 AI 모델 등 별도 설치가 필요한 경우에만 안내한다.
39. 빠른 앱 시작, 필요한 정보만 지연 로딩, 캐시 재사용, AI 작업과 재생의 자원 경쟁 최소화, Android 배터리/메모리 최적화.

### 개발 순서·검증 (40~42)
40. Windows 핵심 기능 안정화 후 Android 개발에 들어간다. 공통 도메인 모델 및 데이터 인터페이스는 재사용하기 쉽게 설계한다.
41. 첫 번째 Windows 테스트는 **검색·상세·회차·실제 재생·로컬 이어보기·한국어 자막 자동 검색/적용·수동 싱크 조절**에 집중한다. 로컬 AI 번역·자동 싱크·클라우드 동기화는 후속 단계에서 검증한다.
42. 오류 발생 시 로컬 진단 로그를 남기고 오류 정보 복사·사용자 주도 문제 신고를 지원한다. 민감 데이터는 기록·자동 전송하지 않는다.

### 아직 결정하지 않은 항목
- 43번 설치 파일/포터블/최종 배포 경로: **보류**. 테스트 개발에 필요한 로컬 빌드는 진행할 수 있다.
- 제품 공식 이름, 클라우드 공급업체, 실제 API·AI 구성, Android UI 기술 선택, 릴리스 일정: 구현 검증 후 결정.
- API 없는 ChatGPT **자동** 번역: 사용자 요구 목표이나 실현 가능성·안정성·이용 조건을 검토한 뒤 별도 판단.

## 3. 단계별 구현 로드맵

### Phase 0. 원본 저장소 점검 및 실행 기준선 마련
- 해당 GitHub 저장소를 별도 작업 디렉터리에 복제하고, 원본 수정 없이 구조를 확인한다.
- README, PRODUCT.md, DESIGN.md, package.json, `electron/`, `src/`, `tests/`, 빌드 설정을 읽고 기능별 담당 파일을 표시한다.
- Node/Electron 버전 및 의존성 설치 방법을 확인하고, 원본 빌드·테스트·실행을 시도한다.
- 기존 공급원, 한국어 제목, 자막, 다운로드, 로컬 번역 기능에 대한 **실제 동작 여부와 실행 불가 이유**를 기록한다. 네트워크 접근권·사이트 정책·테스트 자산 부족 때문에 검증 못 했으면 '미검증'으로 쓴다.
- 1~42 요구사항에 대해 `이미 지원 / 수정 필요 / 신규 구현 / 기술 검증 / 보류` 매트릭스를 작성한다.
- 원본 재사용/재배포 라이선스와 크레딧 조건을 확인한다. 권한이 불명확한 부분은 배포 가능으로 가정하지 않는다.
- 산출물: `docs/BASELINE_AUDIT.md`, `docs/FEATURE_GAP.md`. **이 단계에서는 대규모 기능 변경 금지.**

### Phase 1. Windows 첫 실제 시청 테스트
- 홈·검색·작품 상세의 단순 OTT 흐름 정돈.
- 다중 공급원 검색 및 작품 식별/매칭 안정화.
- 회차 선택→실제 영상 재생→진행 위치 저장→재방문 이어보기 확인.
- 내장/온라인 한국어 자막 자동 탐색·적용, 타이밍 수동 조절 및 안전한 실패 처리.
- 오류 자동 복구, 서버 전환, 간단한 사용자 메시지, 로컬 진단 기록.
- 28번 다음 화 **수동 버튼**과 29~39번 간편 UI 원칙 반영.
- 자동 테스트뿐 아니라 허용된 **실제 재생 가능한 자료**로 성공/실패 사례를 확인한다.
- 이 단계에서 클라우드 로그인을 흉내 내어 완성됐다고 주장하지 않는다. 테스트용 로컬 프로필/개발용 상태는 사용자용 게스트 모드와 구분한다.

### Phase 2. 자막 자동화 고도화
- 한국어 자막 검색 우선과 검색 실패 구분을 확실히 구현.
- 로컬 AI 모델 설치 안내 및 번역 캐시/부분 번역/용어집/품질 검증.
- 일본어 음성 인식→의미 비교→보정 신뢰도 계산→자동 싱크 적용/철회.
- ASS/SSA 원본 스타일 호환성 및 각 자막 형식 테스트.
- API 없는 ChatGPT 자동 번역은 별도 조사 보고서 작성. 지원 가능하다고 검증되지 않았다면 수동 흐름만 구현/유지.

### Phase 3. 계정·멀티 프로필·클라우드 동기화
- Supabase/Firebase 등 관리형 인증·DB 선택에 앞서 비용·무료 한도·보안·개인정보 비교.
- 이메일/비밀번호와 Google OAuth, 로그인 상태 유지, 계정 연계.
- 프로필별 데이터 격리, 로컬 오프라인 저장 및 재연결 후 충돌 처리.
- 시청 위치·기록·즐겨찾기·설정 동기화. 영상 파일은 동기화하지 않는다.
- 자동 로컬 백업, 수동 내보내기/복원, 변경·업데이트 알림.

### Phase 4. 다운로드 및 Windows 안정화
- 허용된 영상의 간편 다운로드/오프라인 보관함/자막 동반 재생.
- 다운로드 일시정지·재개·오류 복구, 파일 손상 검사 및 저장 공간 처리.
- 시작 속도·메모리·CPU/GPU 사용량 분석. 번역 분석 중에도 재생 부드러움 유지.
- 회귀 테스트 및 수동 체크리스트 정리. 운영체제나 실제 공급원이 바뀌면 재검증.

### Phase 5. Android 확장
- Electron 앱을 그대로 APK로 패키징하는 방식에 의존하지 않는다.
- 재사용 가능한 도메인(작품 식별, 검색, 자막 처리 규칙, 동기화 스키마)을 모듈화하고 Android용 재생·네트워크·저장·UI 구성은 별도 검토한다.
- 터치/회전/화면 채우기, 로컬 보관함, 다운로드, 모바일 자막 스타일, Android 인증, 백그라운드 제한 등을 실기기에서 확인한다.
- Windows와 Android 간 프로필·이어보기 동기화 및 충돌 복구 검증.

## 4. Codex가 작업할 때 반드시 지켜야 할 규칙

- 한 번에 한 단계만 수정하고 단계 종료마다 변경 요약, 실행/테스트 결과, 남은 위험을 보고한다.
- 기존 기능 삭제 또는 전면 재작성 전에 수정 이유와 대안을 기록한다. 사용자 요구사항을 임의로 변경하지 않는다.
- 앱 UX는 단순하게 유지한다. 고급 자막 편집기, 게스트/자녀용 프로필, 외부 공급원 확장, 시스템 새 화 푸시, 다음 화 자동 재생은 구현하지 않는다.
- 테스트 통과와 실제 동작 검증을 구분한다. 가짜 모의 데이터만으로 서비스 연동 성공이라고 선언하지 않는다.
- 접근 제어·DRM 우회, 비인가 스크래핑/계정 자동화, 저작권/이용조건 위반을 전제로 하는 구현을 요청하지 않는다.
- 앱에 입력되는 비밀번호·토큰·개인정보를 로그, 리포트, 원격 서비스, 소스 제어에 올리지 않는다.
- 수정 후마다 관련 테스트와 기본 재생·검색·자막 회귀 테스트를 실행하고 실패 사항을 사실대로 기록한다.

## 5. 검증 기준 (최초 Windows 테스트)

1. 앱을 시작하고 기본 홈·검색·작품 상세를 무리 없이 열 수 있다.
2. 한국어 제목으로 검색해 작품을 찾고, 다른 시즌이나 극장판과 잘못 통합되지 않는다.
3. 권한/이용 조건에 맞는 실제 재생 자산에서 선택한 회차 영상이 재생된다.
4. 1회 재생 후 앱을 재시작해 마지막 시청 위치에서 이어볼 수 있다.
5. 정확하게 대응되는 한국어 자막은 자동으로 적용되며, 잘못된 회차 자막은 적용되지 않는다.
6. 수동 자막 시간 조절과 설정 저장이 동작한다.
7. 재생 오류 시 무한 로딩 대신 재시도/대체 서버/간단한 최종 안내로 안전하게 종료된다.
8. 회차 종료 후 다음 화가 자동으로 시작하지 않고, 사용자가 누르는 `다음 화 보기` 버튼만 표시된다.
9. 실패 로그에 비밀번호·토큰·개인정보가 포함되지 않는다.
10. 검증한 항목과 검증하지 못한 항목을 실제 근거와 함께 별도로 보고한다.
